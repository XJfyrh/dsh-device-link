# 设备连接

连接局域网内的 DeepSeek Harness 设备，把任务交给另一台电脑，按授权读取它的文件与会话，并在离线时继续引用已缓存的会话内容。

- **跨设备执行任务**：选择对方工作区，使用执行设备的模型、工具和权限配置，查看进度、续写或停止任务。
- **按需读取资料**：在本地会话用 `@` 引用设备工作区或缓存会话，由智能体搜索和读取相关原文。
- **控制访问范围**：由被连接设备选择可访问的工作区、会话和能力，随时调整或撤销授权。
- **打开远端界面**：获得完整界面授权后，直接打开对方 Harness，处理权限请求等交互。

## 开始连接

安装后，在 Harness 侧栏底部打开 **设备**。两台设备均需运行 DeepSeek Harness **0.2.2-rc.3** 和相同版本的插件。

内置连接使用 HTTP，适合可信局域网。两台设备需能互相访问，并允许防火墙放行页面显示的实际监听端口。

以 A 访问 B 为例：

1. 在 B 打开 **设备 → 允许连接本机**，启用局域网接入。
2. 选择账号关系和授权范围。“同一账号”预填全部工作区、会话正文、任务、文件读取和完整界面权限；工具记录共享默认关闭。“不同账号”和“待确认”预填空范围，可按需勾选。账号关系由 B 的所有者确认。
3. 点击 **生成配对码**，将页面显示的地址和 8 位配对码交给 A。配对码默认 120 秒内有效，使用一次后失效；修改范围后重新生成。
4. 在 A 打开 **设备 → 连接设备**，输入 B 的地址和配对码，例如 `192.168.1.5:47654`。

授权是单向的。若 B 也要访问 A，交换角色再配对一次。

## 选择共享范围

设备面板分别显示 **本机连接的设备** 和 **已授权连接本机**。后者可查看、修改和撤销授权；“已授权”不表示对方当前在线。

| 想做什么 | 在被连接设备上开启 |
|---|---|
| 委派任务 | 选择工作区，启用“允许委派任务”；其他目录填写绝对路径 |
| 分析工作区文件 | “允许搜索和读取工作区文件” |
| 查看会话目录 | “会话目录”，并选择可见会话 |
| 阅读与离线引用正文 | “目录与对话正文”，连接后完成同步 |
| 排查历史工具执行 | 正文同步下的“共享会话中的工具调用与结果” |
| 打开完整 Harness | 全部工作区、全部会话、正文同步和完整界面权限 |

受限工作区任务会校验目录真实路径，并使用执行设备的 `workspace-write` 权限预设。完整界面授权包含对方设备的终端、浏览器和文件能力。

## 使用设备

### 委派和处理任务

选择设备和工作区，点击 **新建任务**。底部可选择执行模型和思考强度；Enter 发送，Shift + Enter 换行。结束后可在同一设备会话继续发送。模型选择只作用于目标会话，设备默认模型不变。

新建任务会归入执行设备上对应的工作区。已授权的目录尚未登记为工作区时，会先在该设备登记；登记或关联失败会显示启动失败，不发送任务。已有会话续写保留原来的归属。

任务需要人工处理时，详情显示 **等待权限处理** 或 **等待回答**。获得完整界面授权后，点击“打开 … 的会话处理”，在执行设备的原生 Harness 页面批准、拒绝或回答；未获得完整界面授权时，到执行设备打开此会话处理。连接插件显示待处理状态，权限决定仍由执行设备处理。

工作区可以收藏。任务总览显示进行中、需要处理和最近任务；**查看任务** 进入对话并定位该轮。草稿和阅读位置按目标保存在当前浏览器，任务持久化在插件状态中。页面关闭、刷新或等待结束不会删除任务；**停止任务** 向执行设备请求取消并等待确认。

### 引用和读取资料

在本地会话输入 `@`，选择 **设备工作区与缓存会话**，或从预览点击 **添加到当前任务**。发送的是资源入口和可读取范围，项目文件与整段会话不会随引用自动加入上下文。智能体根据问题搜索，再读取相关原文；读取资料不会自动委派任务或接续设备上的会话。

点击已发送的工作区引用，直接浏览目录、搜索文件并打开正文；会话引用则显示可读取的消息。对话中的浏览、搜索和读取记录可点击查看当次返回的内容，原文不会被后来更新的文件替换。这些入口复用当前会话中的一个设备预览标签。记录最多保留最近 80 次调用，完整工具历史仍由 Harness 保存。

要提供一段确定的文字，在会话预览或读取原文中选中文字，点击 **引用选中文字**。选中的原文（最多 4,000 字符）及来源随消息发送。需要执行操作时，另行使用 **新建任务** 或继续设备会话。

文件搜索和读取支持授权工作区内的 UTF-8 文本文件，每个文件不超过 512 KB；跳过符号链接、`.git`、依赖和构建目录、`.env` 等配置。搜索最多扫描 1,500 个条目并返回 20 项，可指定子目录缩小范围。读取会校验搜索时的内容版本；文件变化后需重新搜索。

设备离线时，智能体可搜索本机已缓存的对话与获授权工具记录，结果标明缓存时间和是否截断。工作区文件不做离线镜像。历史工具结果描述当时执行情况，不代表当前代码版本。

设备详情提供工作区、会话和智能体列表。正文显示缓存时间和截断标记。未授予正文同步时，任务详情仍显示本机提交的要求与返回结果。网络断开时保留已缓存内容；明确收到鉴权拒绝时清空该设备缓存。

### 管理连接与授权

在 **管理设备** 中诊断连接或断开设备。本机授予其他设备的权限在 **设备 → 已授权连接本机** 或连接设置中修改。收紧权限、撤销授权或关闭接入会关闭关联代理连接并停止活动任务。

## 安装与更新

已安装的用户可直接按上面的步骤连接设备。桌面版包含运行环境；使用 CLI 时需要 Node.js 24 或更新版本，并先启动一次桌面版以创建 `desktop` profile。

### 从 npm 安装

退出占用 `desktop` profile 的 Harness 实例后执行：

```powershell
dsh plugin --profile desktop add dsh-device-link
```

重新启动 Harness，侧栏底部会出现 **设备**。使用其他 profile 时替换命令中的 `desktop`。更新时可指定版本，如 `dsh-device-link@0.5.2`，两端使用相同版本。

### 从安装包安装

在桌面版插件页安装 `.tgz` 文件并重启对应 profile，也可通过 CLI 安装：

```powershell
dsh plugin --profile desktop add <安装包的绝对路径>
```

如果更新时报 `EPERM ... rename ... node_modules/dsh-device-link`，先完全退出占用该 profile 的实例，再重试。从源码链接切换安装包时，报错目录可能仍是指向源码的目录链接；只移除该链接后重装，保留源码目录与设备数据。

从源码构建和安装见 [开发说明](https://github.com/XJfyrh/dsh-device-link/blob/master/CONTRIBUTING.md)。

## 连接遇到问题

- **找不到对方**：使用被连接设备页面显示的实际地址和端口；省略端口时默认使用 `47654`。不要填写路径或账号密码。
- **地址是 `127.0.0.1`**：这是本机回环地址，其他电脑无法访问。将插件配置的 `bindAddress` 改为本机私有局域网 IPv4 后重启。
- **无法连接**：在 **管理设备** 中运行诊断。`address` 阶段检查输入，`tcp` 阶段检查网卡、防火墙和端口，`protocol` 阶段检查两端插件版本及是否误用了 Harness 本身的端口。
- **任务等待权限或回答**：按任务详情的提示打开执行设备原生会话处理；完整界面未授权时，到执行设备上操作。
