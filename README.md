# dsh-device-link

连接局域网内的 DeepSeek Harness 设备，向对方授权的工作区委派任务、查看会话，并在对方离线时引用已缓存的正文。任务使用执行设备的模型、工具和权限配置；获得完整界面授权后，也可以打开该设备的 Harness。

使用说明见下文；实现与协议见 [DESIGN.md](DESIGN.md)，开发和验证见 [AGENTS.md](AGENTS.md)。

## 安装

两台设备都需要 Node.js 24 或更新版本、DeepSeek Harness 和本插件。插件按当前宿主服务契约实现，两端使用同一份插件构建。

在源码目录执行：

```powershell
npm ci
npm run build
dsh plugin --profile desktop add E:/dsh-device-link
```

将示例路径替换为实际源码目录，重启 `desktop` profile。侧栏底部出现 **设备** 入口。

向另一台设备分发时执行 `npm pack`，将生成的 `.tgz` 文件复制过去，再执行 `dsh plugin --profile desktop add <包的绝对路径>` 并重启。打包会先构建源码。

## 配对与授权

内置监听器使用 HTTP。两台设备应位于可信局域网，并允许防火墙放行页面显示的监听端口。

以 A 访问 B 为例：

1. 在 B 打开 **设备 → 允许连接本机**，启用局域网接入。
2. 选择账号关系和授权范围。“同一账号”预填完整范围，“不同账号”和“待确认”预填空范围，可继续调整。账号关系由 B 的所有者确认。
3. 点击 **生成配对码**，将地址和 8 位配对码交给 A。配对码默认有效 120 秒，成功使用一次后失效；修改范围后重新生成。
4. 在 A 打开 **设备 → 连接设备**，输入 B 的实际地址和配对码，例如 `192.168.1.5:47654`。

授权是单向的。若 B 也要访问 A，交换角色再配对一次。

| 需要的能力 | 在接收方设置的范围 |
|---|---|
| 委派任务 | 选择工作区并启用“允许委派任务”；其他目录填写绝对路径 |
| 查看会话目录 | 会话同步选择“会话目录”，并选择可见会话 |
| 阅读与离线引用正文 | 选择“目录与对话正文”，连接后完成同步 |
| 打开完整 Harness | 全部工作区、全部会话、正文同步和完整界面权限全部开启 |

受限工作区任务会检查目录的真实路径，并应用执行设备的 `workspace-write` 权限预设。完整界面授权包含对方设备的终端、浏览器和文件能力。

## 使用设备

选择设备和工作区，点击 **新建任务**。底部可选择执行模型和思考强度；Enter 发送，Shift + Enter 换行。结束后可在同一设备会话继续发送。模型选择只作用于目标会话，设备默认模型不变。

工作区可以收藏。任务总览显示进行中、需要处理和最近任务；**查看任务** 进入对话并定位该轮。草稿和阅读位置按目标保存在当前浏览器，任务持久化在插件状态中。页面关闭、刷新或等待结束不会删除任务；**停止任务** 向执行设备请求取消并等待确认。

在本地会话输入 `@`，选择 **设备工作区与缓存会话**，也可以从预览点击引用。工作区引用供智能体委派任务；会话引用携带发送时的正文快照、来源和缓存时间，点击标签可查看这份快照。

设备详情提供工作区、会话和智能体列表。正文显示缓存时间和截断标记。未授予正文同步时，任务详情仍显示本机提交的要求与返回结果。网络断开时保留已缓存内容；明确收到鉴权拒绝时清空该设备缓存。

在 **管理设备** 中诊断连接或断开设备。本机授予其他设备的权限在 **连接设置 → 已授权连接本机的设备** 修改。收紧权限、撤销授权或关闭接入会关闭关联代理连接并停止活动任务。

## 命令与模型工具

配对与授权可通过设备面板完成，也可使用命令：

| 命令 | 作用 |
|---|---|
| `/device` 或 `/device status` | 本机身份和监听状态 |
| `/device list`、`/device trusted` | 已连接设备、已授权设备 |
| `/device diagnose 地址` | 检查地址、网络和协议 |
| `/device pair 地址 配对码` | 连接设备 |
| `/device open 设备`、`/device sync 设备` | 打开完整界面、刷新缓存 |
| `/device session 设备 会话id` | 读取缓存正文 |
| `/device delegate 设备 \| 工作区绝对路径 \| 任务` | 创建持久化任务 |
| `/device tasks`、`/device task 任务id`、`/device cancel 任务id` | 列表、刷新、停止任务 |
| `/device revoke 设备`、`/device untrust 设备` | 断开出站连接、撤销入站授权 |

`/device allow` 使用“待确认”的空授权生成配对码；要委派或打开完整界面，请在面板选择相应范围。重名设备使用设备 id 操作。

智能体可用 `device_delegate` 创建或续写任务，`device_task` 查询或停止，`device_sessions` 读取缓存或主动同步。委派工具默认等待 300 秒，最多 600 秒；等待结束后仍可用任务 id 跟进。

## 配置与诊断

配置位于 Harness profile 的插件配置项中：

| 字段 | 默认值 | 用途 |
|---|---|---|
| `allowIncoming` | `true` | 配置级接入开关 |
| `listenPort` | `47654` | `0` 自动分配；占用时回退到空闲端口 |
| `bindAddress` | `auto` | 选择私有局域网 IPv4；也可指定本机私网地址或 `127.0.0.1` |
| `deviceName` | 主机名 | 设备显示名称 |
| `pairingTtlMs` | `120000` | 配对码有效期，毫秒 |
| `accessTtlMs` | `60000` | 完整界面访问码有效期，毫秒 |
| `proxyRequestTimeoutMs` | `30000` | GUI HTTP 请求超时，毫秒 |
| `toolsEnabled` | `true` | 注册模型工具和后台同步 |
| `maxPairFailures` | `8` | 配对失败阈值 |
| `failureWindowMs` | `600000` | 失败计数窗口，毫秒 |

`DSH_DEVICE_LINK_PORT`、`DSH_DEVICE_LINK_BIND`、`DSH_DEVICE_LINK_ALLOW` 覆盖相应配置。配置级关闭接入时，需要先修改配置并重启，才能使用界面开关。

连接地址接受私有 IPv4、回环 IPv4 和 `localhost`，省略端口时使用 `47654`。不要填写路径或账号密码。诊断停在 `address` 时修正输入；停在 `tcp` 时检查网卡、防火墙和实际端口；停在 `protocol` 时检查插件端口及两端构建。

若监听地址显示 `127.0.0.1`，其他电脑不能接入。将 `bindAddress` 改为本机私有局域网地址后重启。每次连接以页面显示的实际端口为准。

## 数据与验证

状态文件是 `$DSH_HOME/device-link/devices-v2.json`；未设置 `DSH_HOME` 时位于用户主目录的 `.dsh` 下，包含配对关系、令牌、收藏、任务和缓存。读取器要求完整的当前顶层结构，不补齐旧格式。解析或结构错误先保存 `.corrupt-时间戳` 备份，再创建新的设备身份，需要重新配对；文件访问或备份失败则报错并保留原文件。

```powershell
npm run typecheck
npm test
npm run build
npm run test:e2e:protocol
```

最后一项启动两个隔离 Harness，验证真实宿主的配对、代理、持久化任务失败回传、授权和缓存，不配置模型凭据。真实模型与浏览器验证方法见 [AGENTS.md](AGENTS.md#双实例验证)。本次运行结果写入 `.e2e/acceptance.json`。
